# ESPN's Pro Bowl week gap — status and what to verify

## The assumption

Through the 2025 NFL season, ESPN's scoreboard API reserved postseason week 4 for the
Pro Bowl (an exhibition, not part of the actual bracket), which pushed the Super Bowl
to raw ESPN week 5 instead of the 4th real playoff round it actually is:

| Round | Real bracket position | ESPN raw week (season ≤ 2025) |
|---|---|---|
| Wild Card | 1 | 1 |
| Divisional | 2 | 2 |
| Conference Championship | 3 | 3 |
| Pro Bowl (exhibition, not tracked) | — | 4 |
| Super Bowl | 4 | **5** |

This is confirmed by three independent, previously-uncoordinated spots in the codebase
that all separately hardcoded the same workaround before this fix:

- `GameHelpers.GetWeekFromEspnWeek` — the week→`WeekId` translation
- `GameHelpers.GetEspnRequiredPicks` — `"ESPN Treats Post Season Week 4 as the Pro Bowl - this sucks"`
- `Server/Services/ESPNApiService.cs`'s `FixEspnProbBowlWeek` — rewrites a live response's
  `Week.Number` from 5 back to 4 after fetching, for display/team-matching purposes
- `nflAdapter.ts`'s `weekLabelFn`/`postSeasonWeekOptions: [1, 2, 3, 5]` — `"Skip week 4
  (Pro Bowl) — Super Bowl is week 5 in ESPN's 2025 postseason"`

## What changed (2026-08-26)

The NFL discontinued the Pro Bowl **game** entirely starting with the 2026 season —
players are still named to the Pro Bowl as an individual honor, but there is no longer
an AFC vs. NFC game or the flag-football "Pro Bowl Games" format that replaced it.
([Sports Media Watch](https://www.sportsmediawatch.com/2026/08/nfl-pro-bowl-game-discontinued/),
[Yahoo Sports](https://sports.yahoo.com/articles/nfl-eliminates-pro-bowl-game-231023024.html))

With no event to reserve a slot for, ESPN's postseason week numbering is **expected**
to close the gap starting with the 2026 season — Super Bowl becoming raw ESPN week 4,
same as any other round:

| Round | Real bracket position | ESPN raw week (season ≥ 2026, unverified) |
|---|---|---|
| Wild Card | 1 | 1 |
| Divisional | 2 | 2 |
| Conference Championship | 3 | 3 |
| Super Bowl | 4 | **4?** |

## Why this can't be verified yet

The 2026 season's postseason bracket doesn't exist until the regular season concludes
(~early January 2027) — no query against ESPN's live API today, however constructed,
can return real 2026-postseason week-numbering data, because that data hasn't been
generated by ESPN yet. (Also: this sandboxed dev environment's outbound IP is blocked
at ESPN's edge/CDN level regardless — a real deployed environment, e.g. Railway, isn't
necessarily affected, but that's a separate, unverified concern from the data
availability question.)

## The fix (2026-08-27)

`GameHelpers.GetWeekFromEspnWeek(long week, int season, bool isPostSeason)` is gated by
**season**, not by a raw-week heuristic:

```csharp
private const int LastSeasonEspnSkippedProBowlWeek = 2025;

public static int GetWeekFromEspnWeek(long week, int season, bool isPostSeason = false) {
    if (!isPostSeason) return (int)week;
    if (season <= LastSeasonEspnSkippedProBowlWeek && week == 5) return 22;
    return (int)(week + 18);
}
```

For season ≤ 2025, raw week 5 is explicitly remapped to WeekId 22 (Super Bowl). For
season ≥ 2026, no such remap happens — raw week 4 already resolves to WeekId 22 via the
plain `week + 18` arithmetic, matching the "gap closed" assumption above. If that
assumption turns out to be wrong (ESPN keeps reserving week 4 for some other reason, or
renumbers differently), a real week=5 postseason response for 2026+ maps to a
**nonexistent WeekId 23** — this fails loudly (no matching `NflSeasonWeekConfig` row, no
persisted scores, `doOddsExist` empty) instead of silently coinciding with the right
answer by accident. That's deliberate: better a visible failure than a quiet wrong guess.
